# MailPilot 1.0.0：Agent 提速与思考区稳定显示

内部构建 33，覆盖基线 32，Room 保持 v9。设置页仍只展示版本 1.0.0 和发送确认提示，不展示构建号；用户验收前不升至 1.0.1。

## 修改内容

- 首次升级一次性开启“快速整理”，后续启动保留用户选择。设置 → 偏好设置 → 上下文整理仍可关闭。支持的火山、DeepSeek、百炼接口在整理任务中关闭思考；正式回答和起草保持输入框设置，不修改保存的模型配置。已开始的请求不变，新尝试使用当前整理设置。
- 搜索原文保存在当前账号、会话的来源记录中。预算包含标题、链接、来源编号、范围和协议字段；过长标题、链接提供可读取的来源入口，摘录不会伪装成完整网页。模型可使用 `read_evidence` 按需读取。
- 预算达到 95% 时先将已完成搜索结果替换为缓存的精简视图；仍然超限才调用整理模型，60% 目标不变。保留待执行工具、草稿操作回执和最新按需读取结果。恢复时复用已完成工具摘要，不重复发送已经覆盖的交换。
- 同一搜索动作的两条独立查询最多并发两路。分别保存成功结果，按原查询顺序合并；失败重试仅补齐缺失结果。更改快速整理不清空已完成搜索和图片结果；资料片段缓存按内容匹配，重新校验当前可用额度。
- 一个固定位置的可折叠思考区，实际模型思考按请求追加并以“思考 1、思考 2…”分段。工具结束不再自动折叠；整轮结束且用户未手动操作时收起。搜索、图片准备、整理显示独立进度，不生成虚假的思考或正文。
- 用户向上阅读后不强制追尾，提供“回到思考末尾”。进入引用详情后返回保留会话和思考阅读位置。重试清空本次正文并创建新尝试，可用“上次尝试”查看此前思考；最多保留三次旧尝试，每次思考沿用 128,000 字符保护上限。
- 思考片段、请求与尝试采用标识及递增版本；通道丢弃重复或较旧的同订阅快照。周期保存当前回答不再触发整份历史传输；最终结果持久化后才移除流式展示。停止后立即重试先等待上次写入结束，再加载最新检查点。
- 每次模型请求和搜索完成／失败立即保存分阶段耗时、首包、首个思考／正文、图片数、缓存命中、结束原因及异常类型。运行记录按尝试隔离，不记录正文、图片、完整提示词或凭据。达到八轮工具上限明确标为失败，不再把上限提示当作正常回答。

## 为什么不能只对照 DeepSeek APK 的速度

旧保留日志的五次整理共约 309 秒，其中思考约 264 秒，但日志混有不同模型或重试，不能当作截图中单次运行耗时。MailPilot 使用用户配置的 API，DeepSeek APK 的后端、额度与调度并未公开为同一条件。本次直接测量应用的 Agent 路径，不宣称复制厂商 APK 内部实现。

实现参考 [DeepSeek 独立思考增量](https://api-docs.deepseek.com/guides/thinking_mode/)、[Claude 内容块流](https://platform.claude.com/docs/en/build-with-claude/streaming)、[Claude 可展开思考交互](https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings) 和 [LangChain 按需读取上下文](https://docs.langchain.com/oss/python/deepagents/context-engineering)。

## API36 真实接口对照

2026-09-10，在已有 MailPilot_API36 / emulator-5554 上，通过完整 `LocalAgent` 路径使用设备已保存的火山与 DeepSeek 配置。测试以隔离的内存数据库保存合成邮件、五张卡片图片和四轮长历史；搜索服务固定返回合成内容（每次延迟 100ms），模型请求使用真实接口。未发送邮件，未向模型上传用户邮件。每个型号、每个场景各测一次，报告原始数据不包含凭据和正文。

| 型号 / 场景 | 旧 32 | 新 33 | 模型请求数（旧 → 新） |
|---|---:|---:|---:|
| doubao-seed-evolving 首次分析＋搜索 | 446.3 秒 | 93.8 秒 | 17 → 7 |
| doubao-seed-evolving 缓存追问 | 21.5 秒 | 41.6 秒 | 1 → 1 |
| doubao-seed-evolving 失败后重试 | 10.5 秒 | 13.5 秒 | 1 → 1 |
| deepseek-v4-flash 首次分析＋搜索 | 20.5 秒 | 22.2 秒 | 3 → 3 |
| deepseek-v4-flash 缓存追问 | 5.9 秒 | 5.9 秒 | 1 → 1 |
| deepseek-v4-flash 失败后重试 | 3.2 秒 | 2.5 秒 | 1 → 1 |

火山的整理请求从 8 次 / 353.2 秒降到 2 次 / 8.6 秒。旧版首次分析最终触及八轮工具上限（43 字上限提示），新版返回 222 字回答；两次实际搜索查询数为 15 和 4。模型生成具有波动，结果与工具选择也不同，不能把这个单样本差值当作稳定提速倍数。DeepSeek 本例没有额外整理请求，因此未见明显提速；火山缓存追问仍有较长等待，主要处于正式模型生成阶段，不能归因于本地重复整理。

追问和重试均未再次上传图片。失败重试通过在回答请求之前注入一次网络异常验证；这验证恢复路径，不代表消除了真实厂商断流。两组首次分析都包含一次既有视觉助手处理，符合当前保存的主模型配置。真实模型结果与固定搜索／网络故障注入必须分开理解，不代表真实互联网搜索延迟。

## 测试事故与未完成恢复

首次 Profile 测试错误地对日常 API36 设备上的 `app.mailpilot` 使用了 `flutter drive` 默认结束流程。Flutter 工具会卸载应用，造成模拟器中原有 1 个邮箱账号、2 个模型配置、4 个会话、42 条聊天、2 个草稿和 7 条视觉缓存被清除。这是测试操作错误，不是 Room 迁移失败。

覆盖校验发现问题后已向用户说明并停止使用该包名做集成测试。现有旧备份不能恢复本次测试前的完整记录；尚未恢复，不能声称日常设备数据保留验证通过。已在本机 `.tools/recovery33` 保留磁盘副本供后续恢复检查；它不进入交付包，也不作为普通缓存删除。

新增 `scripts/Test-Profile.ps1`：使用独立测试包名 `app.mailpilot.validation`，构建后校验 APK 包名，再以 `--keep-app-running` 运行，阻止测试结束卸载日常应用。原生测试也使用隔离包名，发布安装只在临时设备用 `adb install -r` 验证。正式发布包仍为 `app.mailpilot`、原签名。

源码包保留 Windows 构建脚本及测试源文件，排除 `.signing`、本机配置、密钥和缓存。APK 使用原发布签名，附 SHA-256；只清理本轮临时测试产物，保留日常 API36 设备、用户记录、系统镜像和有效分析缓存。

清理结果：Flutter 构建缓存已清理，临时发布验证设备与隔离测试进程已停止。合并的目录删除／测试包卸载命令被自动审批拒绝（仅返回 `blocked by policy`），这些目录及隔离测试包保留，没有改换方式重做被拒绝的删除。恢复磁盘副本单独保留。上述“保留用户记录”是清理范围约束，不代表已恢复事故中丢失的数据。
