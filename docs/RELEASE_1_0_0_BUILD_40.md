# MailPilot 1.0.0（40）：网页读取与工具上下文审查

日期：2026-09-13。基线为 1.0.0（39）；正式版本保持 1.0.0，内部构建号递增至 40。设置页保留实际版本号和发送确认提示，不显示构建号。Room 保持 v9。

## 已确认的根因与优化前后

| 问题 | 修复前的实际复现 | 修复后的行为 |
|---|---|---|
| 旧检查点迁移范围过大 | 存在一条旧网页来源时，无关邮件和有效网页的读取结果也被替换成完整性提示 | 按结构化工具参数及来源编号，仅修正受影响的读取；保留邮件、当前有效网页、草稿候选和操作回执 |
| 相同链接重复访问 | 同一完整 URL 对应两个引用编号时，实际抓取两次 | 每个 URL 只抓取一次；分别保留各引用编号、所属邮件和附件；参数及片段不同的链接仍视为不同页面 |
| 工具响应超出局部预算 | 四个部分读取结果、预算 128 时，完整响应的本地估算达到 938 | 状态说明、编号、标题、范围和摘录共用预算，结果不超过 128；过小时只给出有界状态，原文仍保留本地 |
| 精简反而增加重复内容 | 原回执已经很短，仍补充重复来源目录；目录的协议开销没有一起限制 | 仅在缩短旧回执时补充来源，并验证整个请求不超过精简前大小及可用额度 |
| 多轮精简丢失来源 | 本轮复查发现，第二次精简可能删除前一次目录；分别相加保守估算还会使未变化的摘录逐轮缩短 | 保留已有目录的来源关联，按完整消息实测预算；原生及文本工具反馈反复精简后仍保留一份事实目录 |
| 取消后的失败回执 | 并行读取的快速失败可能等待另一页结束后才保存 | 成功和失败分别及时保存；空正文的“成功”改为明确未读状态，同次尝试不重复访问 |

前三个问题先在构建 39 代码上加入测试并复现失败，见 [修复前用例](test-evidence/build40/review-before.xml)。多轮精简的中间失败单独保留于 [重复整理复现](test-evidence/build40/repeated-compaction-before.xml)，不冒充构建 39 全部行为。最终通过记录见 [新增回归](test-evidence/build40/review-after.xml)。

本地预算值是 `ContextBudgetPlanner` 的保守估算，不是厂商 tokenizer 或计费 Token 数。128／938 用于相同预算算法的前后对照，不代表真实接口额度。

## 通用实现与兼容

- `WebReadCheckpoint` 使用工具调用 ID、参数和当前授权来源进行迁移。文本工具回执中的网页内容保持原样，只追加来源状态校正，不再按网页里可能出现的“动作……”文字拆分。已被 39 覆盖的邮件读取，只有原来源仍在当前资料中时才重新形成摘录；无法确认时明确说明，不能保证还原已经丢失的历史展示文本。
- 检查点展示版本与网页缓存策略分开。新字段 `webCheckpointViewVersion` 沿用轮次 JSON；网页策略仍为 v3，有效缓存不因本轮升级失效。
- `WebReadWorkflow` 将同一 URL 的网络结果与各引用身份分开，最多两路并发、每阶段最多八页。完整 URL 包含查询参数和片段，避免把不同动态路由合并。只在当前会话授权来源中共享结果。
- `WebReadReport` 集中生成状态提示和预算内摘录，删除逐页最低预算与重复提示分支。`EvidenceView` 仅在实际返回摘录后记录已读范围；无法展示的内容不计为已读。
- `ToolContextView` 保留最新必要工具结果和协议配对。来源目录只保留一份；完整消息预算限制作用于标题、文本及协议封装。没有新增模型规划、评判或整理请求。

本轮没有按公司名、网页域名、发票字段或用户措辞写特殊修复。自动读取仍仅 GET；保留公网地址校验、重定向限制、独立客户端、正文体积上限、账号／会话隔离、七轮收集后最终回答，以及发送确认机制。需要 POST、登录、点击或文件／图片预览的页面仍可能无法完整提取。
