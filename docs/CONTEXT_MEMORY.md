# 模型上下文与可恢复整理 · 1.0.0（31）

MailPilot 原先已有滚动摘要。“摘要未满足长度要求”来自应用的空值或固定 4,000 字符校验，不能据此判断厂商上下文已满。本轮替换该校验和分散的字符预算计算。原始聊天始终保留，摘要是有损参考资料，不是新的操作授权。

## 统一预算

`ModelCapabilityResolver` 按官方接口与确切型号提供总上下文、最大输入、思考模式差异、最大输出、来源及核实日期。`ModelContextPolicy` 沿用 DataStore 保存跟随型号／自定义：已知型号旧 32,768 默认值自动匹配，其余已有值保留。未知型号、别名和代理地址使用手动额度。视觉助手按自己的型号计算。

`ContextBudgetPlanner` 取用户与厂商上限的较小值，预留输出；火山 `max_tokens` 另留思考空间，其他已知接口同时受该思考模式的输入上限约束。输出默认跟随已核实型号最大值：规划历史时保留基本回答空间，最终请求根据实际图文、工具与历史的估算占用，分配剩余空间内的最大输出。自定义模式仍预留用户填写的完整额度。未知接口自动模式暂用 4096，不推断厂商最大值。火山本地思考预留不等同于厂商的实际消耗。详见 [输出策略](RELEASE_1_0_0_BUILD_29.md)。

每次发送模型请求前，`PreparedModelRequest` 冻结逻辑消息和工具定义并通过统一预算检查；图片保留文件引用，继续流式编码。按解码后的内容估算系统提示、工具定义、问题、历史、资料和工具结果；传输 JSON 的转义及 Base64 字节由请求体上限单独管理。确实写入 content 的转义字符仍计入文本。文本取 UTF-8 字节数与 UTF-16 长度两倍的较大值；已核实的图片规则计入输入预算，未知规则的 8192 Token 值只用于诊断。**本地估算不是厂商 Token 计量或计费数值。**

预计输入达到有效预算的 **95%** 时先整理，目标是 **60% 或以下**。新增资料或工具结果越过阈值也执行整理；底层 HTTP 客户端另有最终输入预算校验。历史和资料共享空间，已删除固定三分之一分配。最近两轮完整对话与当前问题不截断；它们或必需内容自身无法容纳时，要求用户调整资料或配置。

95% 是本轮明确的产品策略。此前看到的 Codex 有效上下文比例不代表本会话真实自动压缩阈值，MailPilot 不宣称复制其内部机制。[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

## 分批整理和恢复

`ContextReducer` 使用 `CompressionPacker`，将系统提示、旧摘要、新片段及实际内容包装一起估算，以本地二分缩小当前片段，优先按换行和 Unicode 边界切分。每批都在调用前满足预算。近期原文单独保留，60% 是目标而非新的硬上限，近期必需内容较大但仍可提交时允许保留。

网页全文仍保存在本轮来源和动作检查点；`EvidenceView` 先提供逐来源摘录、已覆盖位置和下一位置，模型可以通过受限 `read_evidence` 继续读取本轮已授权来源。该动作不下载网页、不访问文件路径、不读取其他账号或未选中的邮件。摘录不被标为完整原文。原生工具保持调用／结果配对；文本适配器不再重复 JSON 包装整份结果。

- 摘要提示保留用户目标、约束、关键姓名／日期／金额、后续修正、待办、来源和不确定性。
- 建议输出长度与实际摘要上限分开；略超过建议但仍在预算内的摘要可以接受。
- 完整但过长的候选最多额外精简两次，按轮次累计，而不是每批各两次。
- 空值、格式错误、输出截断、网络异常、精简后超限分别反馈。模型摘要请求没有工具，不会发送邮件。
- 每个有效批次保存来源块及字符位置、摘要、精简次数和策略版本；完整但未校验的候选独立保存，精简断流后可继续。单次最多推进 24 批；候选过大时精简请求自身也动态装填，总额外请求仍最多两次。
- 所有批次有效后，通过包含原记忆与范围条件的更新提交正式摘要和覆盖位置；并发改变、取消或失败不会用无效候选覆盖旧记忆。
- 检查点包含会话／账号范围、历史和资料内容、模型连接及凭据版本、实际思考和预算身份。相关内容变化时重新计算。
- 检查点放在轮次 JSON，重启后仍在。重试复用成功批次；新请求不自动执行上次失败操作。本轮 Room 保持 v9（构建 24 已迁移），压缩检查点仍沿用轮次 JSON。

资料仍按选中范围读取；取消选择后，历史摘要可以继续引用已有观察，但不会重新读取原文件。回答转邮件复用完整目标回答及已处理资料，不重新读图。压缩不修改草稿版本或发送状态。

## 交互与诊断

仅整理期间显示进度；完成后通过会话菜单查看摘要。输入框上方没有常驻整理条数。失败保留原问题和资料快照，预算错误提供查看预算、调整资料、修改配置；整理中断提供继续整理。新失败不混入上一个成功请求的结束原因和时间。

诊断记录阶段、型号、输入预算、估算长度、批次、结束原因与异常类型，不记录密钥、邮件正文或完整提示词。只展示真实返回的思考内容。

参考 [LangChain 短期记忆](https://docs.langchain.com/oss/python/langchain/short-term-memory) 的摘要与近期消息保留方式，以及 [CoMem](https://arxiv.org/abs/2605.30842) 的研究方向；本版不引入独立摘要服务或框架，仍由当前手机直连模型执行。有损摘要的事实质量需要真实模型验收，模拟测试不能证明所有细节都不会遗漏。

本轮测试与限制见 [构建 22](RELEASE_1_0_0_BUILD_22.md)。早期 1.3 机制与历史验证归档于 [历史记录](CONTEXT_MEMORY_HISTORY_1_3.md)，不再作为当前预算规则。
