# MailPilot 1.0.0（37）：读取所选邮件中的链接

## 使用方式

选择邮件后直接输入“总结所选邮件，并查看里面的链接内容”或“打开邮件中的查看记录链接”。不必复制网址，也不必先配置搜索服务或开启智能搜索。Agent 会根据当前要求调用网页读取工具，并按实际读取结果回答、标注来源。

普通总结不在本地预先打开所有链接；是否需要读取由当前任务与工具决策确定。开启智能搜索仍可发现额外公开资料，直接读取已有链接和搜索关键词是两个独立能力。

支持 HTTP／HTTPS 的无登录 HTML 和纯文本网页。页面要求登录、验证码、JavaScript，或返回 PDF、图片等文件时，当前读取器不会声称已取得其内容；会提示用浏览器查看，或下载文件后添加到本轮资料。此轮没有增加自动登录、执行网页脚本、提交表单或点击支付／确认按钮的功能。

## 根因与优化前后

截图中的邮件按钮只显示“查看发票”或“了解详情”。邮件存储实际上保留了清理后的 HTML，但 Agent 只使用纯文本正文，导致按钮的 `href` 地址没有进入上下文。另一方面，原 `read_web_page` 工具跟随智能搜索开关，并且只允许已登记为网页来源的对象；邮件正文中的普通 URL 也未登记。因此模型没有可调用的邮件链接来源。

| 方面 | 之前 | 现在 |
|---|---|---|
| HTML 按钮 | 只向模型提供按钮文字 | 从已保存 HTML 读取真实 `href`，保留按钮文字及所属邮件 |
| 纯文本链接 | 只是正文的一部分 | 完整 URL 登记为独立来源编号 |
| 文字附件链接 | 没有可访问的来源编号 | 只从本轮已处理、已选择的文字附件提取并登记 |
| 搜索服务 | 网页读取跟随智能搜索开关 | 所选资料有链接时直接提供读取工具，不依赖搜索服务 |
| 访问方式 | 可能反复解释“没有工具” | 根据当前工具定义按来源编号读取，不猜地址、不需要先搜索 |
| 失败反馈 | 统一保留“搜索摘录” | 保留原邮件／原资料，区分登录、动态页面、文件、超限、超时、连接和地址限制 |
| 再次提问 | 邮件链接没有复用路径 | 当前账号、当前会话且当前仍选中的同一资料链接可复用已完成网页内容 |
| 旧能力描述 | 历史“不支持链接”可能影响回答 | 系统明确以当前工具定义和读取状态为准 |

## 实现与代码审查

- 新增 `SelectedLinks`，仅负责离线提取和来源登记。HTML 解析使用已有 jsoup，提取 `a[href]`，不会加载图片、脚本、CSS 或跟踪像素。不根据“发票”“GitHub”等主题硬编码访问路径。
- 真实目标以 `href` 为准，显示文字伪装成其他网址时不会将伪装地址一并作为真实按钮目标。没有完整地址的按钮、相对地址、mailto、javascript 和嵌入用户名／密码的地址不被猜测或补全。
- HTML 实体由 HTML 解析器正确处理，百分号编码和查询参数保留；不会将邮件链接交给搜索服务解析。纯文本提取区分中文标点与 URL，保留配对括号。
- 本轮最多登记 64 个去重链接，超出时明确提示缩小所选范围；地址最大 8192 字符。链接元数据进入统一请求预算，不在预算之外追加。
- `AgentActions` 继续负责唯一的工具 schema 校验，`read_web_page` 仍只接收当前来源编号，不接收模型任意构造的网址或其他邮件 ID。网页读取与搜索能力分开，未新增独立执行循环。
- 复用现有 `WebReadWorkflow`、`PublicWebReader`、`WebEvidenceStore` 和检查点。取消选择不会从历史来源列表重新开放原邮件链接。跨账号与会话不共享缓存，修改目标地址会形成新来源。
- 修复恢复时旧占位链接遮住已经保存网页正文的合并顺序；此前网页复用按所属资料及 URL 匹配，避免搜索结果继承另一封邮件的私有来源身份。
- 移除系统提示中“互联网资料只能是搜索服务片段”的旧描述。模型必须区分发现地址、邮件原文、搜索摘录、已读网页正文以及未读成功状态。
- 保留独立无凭据网络客户端、公网目标和实际 DNS IP 校验、每次重定向重新检查、HTTPS 不降级、三次重定向、30 秒单页时限、2 MiB 解压后响应上限、每阶段八页／最多两路并发。
- 内容仅为参考，不产生额外工具权限或发送授权。无 SMTP 工具，邮件／草稿原状态不被读取流程修改。新增诊断不记录链接参数、邮件正文或凭据。

技术依据：[jsoup 属性与链接提取](https://jsoup.org/cookbook/extracting-data/)、[OWASP 请求目标与重定向校验](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 测试范围

新增回归覆盖隐藏按钮地址、HTML 实体、纯文本中文标点、配对括号、显示地址与真实地址不一致、无地址按钮、邮件和脚本协议、图片跟踪地址、完整查询参数、有工具／无工具模式、关闭搜索时直接读取、普通总结不预取、取消选择、未选择邮件与附件、任意来源编号拒绝、登录／动态／文件／超大响应，以及保存、序列化和重启后的复用。

完整 Agent 测试以合成通知和链接验证：一次网页读取、两次模型请求、没有搜索请求、返回可引用的网页正文、零草稿。跨账号／会话及网页重定向、非公网目标、并发、取消和大小限制沿用原有回归。

截图中的真实发票链接没有用于联网实测；其是否需要登录、JavaScript 或直接下载文件不能从截图确定。真实厂商验证使用合成邮件内的公开文档网站链接，与固定响应测试分开记录。

## 验证结果

- Flutter：**383 项通过**，静态分析无问题。
- 原生：**276 项，274 通过、2 项真实 IMAP 条件测试跳过，0 失败**。
- Android Lint：**0 错误、13 项既有提示**。
- 现有 MailPilot_API36 / emulator-5556：使用已配置的 **doubao-seed-evolving**，临时数据库中放置一封带有隐藏 `href` 的合成邮件，目标为 jsoup 公开网站；关闭智能搜索。首次真实测试 **14.593 秒**；补全资料目录中的链接编号后，最终复测 **19.518 秒**。两次均为 **2 次模型请求、0 条搜索查询、1 次网页读取、完整回答、0 草稿、无协议泄漏**。不是对发票网站的可访问性结论，也不以两次生成耗时差异断言性能改善或退化。
- 同次设备运行也保留 DSML 合成协议回归，两项设备测试通过。日常应用没有加载测试邮件，不读取真实邮箱邮件，也不发送邮件。
- 最终复测有一次被设备上同期的强制停止／覆盖安装中断，测试运行器报告 `Process crashed`；系统日志显示进程因强制停止被终止。该次不计为通过，随后重新运行两项测试成功，保留[中断记录](test-evidence/build37/api36-interrupted.log)。
