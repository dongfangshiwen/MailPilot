# MailPilot 1.0.2（17）

本版继续使用 Flutter、手机直连邮箱与模型，沿用原发布签名。Room 保持 v8，已有数据无需重建。

## 单封邮件的默认收件人

只选中一封邮件并让助手起草时，默认将该邮件的发件人邮箱填入收件人。直接提供“写给 xxx@example.com”或“发给 xxx@example.com”时，明确目标优先。多封邮件不猜测目标，发件人地址无效则留空。只读取邮件头的发件人地址，不从正文中的指令获取其他收件人；抄送和密送仍需用户指定。

重新拟写已有草稿默认保留原收件人及附件。邮件仍先展示确认卡片，核对后再点击确认发送或在最新卡片后发送明确确认指令。

## 修改已发送的问题

点击用户气泡右下角的铅笔，底部输入框切换为“修改输入”。可以编辑文字、调整本轮思考或搜索选项，然后点击发送。普通输入尚未发出的内容会暂存；点 × 取消时恢复，历史记录不变。

重新发送会从这条问题的位置生成新的回答，新的模型上下文不包含被替代的回答和后续分支。原问题、回答以及 SMTP 审计仍保存在本机。气泡下方的版本入口可以查看旧版本，旧版本只读，不提供发送按钮；继续聊天始终使用最新分支。旧分支下的实际草稿与已发送邮件不会被删除或撤回。

修改问题沿用原轮次的邮件、附件和实际 PDF 页码快照；修改面板显示资料数量，添加附件入口在编辑时禁用。若希望使用另一组资料，请取消修改后作为新问题提问。原资料已被清理时会明确提示。具有可恢复快照的历史提问支持修改，应用的发送确认记录和没有快照的旧消息不提供修改入口。

生成过程中可先停止回答再修改。“确认发送”作为修改后的问题不会调用 SMTP；需要在最新的真实邮件确认卡片后重新确认。

## 修复草稿代码输出

原因是历史上下文曾把整张确认卡片序列化为 JSON，模型将其当作回答范例照抄；非起草分支又直接显示模型文本。

- 历史上下文改为可读的收件人、主题、正文和附件名称；不传私有文件路径，不把确认卡片 JSON 作为聊天示例。
- 起草意图统一走结构化草稿解析或草稿工具。内部 JSON 不进入聊天流；正式内容由本机确认卡片显示。
- 若普通回答仍返回内部草稿对象，会先校验真实草稿与版本。内容完全匹配的本会话草稿可重新展示确认卡片；不匹配时明确提示未保存、未发送，不将模型打印的数据冒充可发送草稿。
- 已保存的旧 JSON 回答在展示时转换为可读的历史邮件正文，原记录保留。普通编程问答中的代码块继续正常显示；流中的潜在 JSON 片段先暂存，完成分类后展示。

## 最大输出长度

新建模型默认最大输出长度为 **4096 Token**，界面、原生模型配置和请求回退值保持一致。已有模型保留其已保存数值；需要增加时，在“模型设置 → 高级参数 → 最大输出长度”填入 4096 并保存。实际可用上限仍取决于模型接口，同时要求最大输出长度小于配置的上下文长度。此默认值不改变已保存模型的思考档位。

## 安装与构建

安装 `MailPilot-1.0.2-flutter-release.apk`，直接覆盖已有版本，不要先卸载。设置页读取 APK 实际版本 1.0.2，内部构建号 17。

Windows 构建：

```powershell
./scripts/Build.ps1 -Mode Test
./scripts/Build.ps1 -Mode Release
./scripts/Package-Delivery.ps1
```

沿用原签名文件，并单独备份 `.signing/`；签名材料不包含在源码和交付包中。发布证书 SHA-256：`0be84c66d74a7a2f8ccd8a39ee792f0c3b22fd942600307164f38ff93b3f2f17`。
