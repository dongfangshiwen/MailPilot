# MailPilot 1.0.0（30）：通用动作流程与搜索恢复

正式版本保持 **1.0.0**，内部构建号由 29 递增至 30，沿用原发布签名。设置页不显示构建号，Room 保持 v9。

## 两个问题的原因

- 搜索反复追问关键词：原来的专用规划提示词禁止使用邮件、附件和历史，只看当前一句话。因此“邮件里面的内容”“附件相关信息”无法承接已有语境。旧关键词路由还会把“重新搜索”里的“重新”判为重拟，把已有草稿时出现的任意邮箱地址判为起草。
- “格式不完整或不兼容”：代码存在可复现的缓存错误。第一条查询完成后，第二条尚未缓存的查询经 `optString` 变成空字符串，再传入 JSON 解析器而失败。随后只读检查 API 36 设备最近两次失败记录：火山模型均以 stop 正常结束，均有两条查询、第一条已缓存 5 个结果、第二条缺失，与此代码路径吻合。设备当时仍运行修复前的中间构建。本轮已用双查询及断线重试测试复现并修复该路径。脱敏诊断见 test-evidence/build30/observed-device-failure.json。

## 现在的 Agent 架构

采用 **完整上下文 → 模型选择动作或直接回答 → 应用校验执行 → 结果反馈** 的有界循环。

`AgentActions` 是统一能力目录及参数校验入口。支持原生工具的模型使用原生调用；不支持的模型使用 `mailpilot_action` JSON 协议，最终进入相同的校验和执行代码。普通答案仍使用 Markdown。可能是内部动作的 JSON 在验证前不会流进聊天气泡；参数缺失、类型错误、未知操作和截断动作会返回明确的可重试错误。

可用动作包括联网搜索、当前邮箱卡片检索、创建草稿及修改本会话草稿。动作只在对应条件满足时开放：搜索开关控制联网工具，邮箱连接控制邮件工具；已有所选邮件时，不开放检索其他邮件的动作。每轮最多四个工具，最多八轮，相同调用无新结果时停止。

自然语言不再依靠“重新”“写邮件”“发给”等关键词决定路由。模型结合当前要求、有效历史、记忆和所选资料判断任务；普通聊天不增加独立的分类请求。明确的“写成邮件”、重拟按钮仍直达现有可恢复起草工作流，保持有效思考设置与草稿预览。

确定性的账号隔离、参数限制、资料预算、草稿版本检查和发送确认继续由应用负责。模型没有 SMTP、删除邮件或读取未选正文的工具。发送只能经过最新正式卡片的用户确认；动作失败不会覆盖原稿。

## 搜索、图片与恢复

搜索动作从完整且经过统一预算检查的上下文提取必要公开主题；不再维护另一份只看当前句子的搜索上下文。完整请求仍遵守既有 95% 触发、60% 目标的压缩规则。

`SearchWorkflow` 仅负责校验公开关键词、调用搜索服务及保存结果，不另行猜测用户意图。每个搜索动作最多两条、每条最多 100 字。应用过滤常见邮箱、电话、明显凭据和 URL 私有路径／参数；提示词禁止提交私人通信全文和内部标识。此过滤不等同对任意私人信息的完备识别。

普通视觉问答仍可一次提交图文。需要联网检索图片里的内容时，先读取尚无有效观察的图片，再把观察用于动作选择和最终回答，同一轮不重复上传。已完成观察及文件处理结果继续在当前账号、会话中复用。

`AgentActionCheckpoint` 记录已完成的动作交换、待执行决定、成功结果和候选草稿。检索结果逐条保存；第二条失败后，手动重试只补查第二条。最终回答失败后，重试复用已完成动作，只重新生成回答。新尝试不拼接旧的部分答案。

检查点与账号、会话、当前问题、资料、历史、实际模型、工具模式及配置绑定；相关内容变化会重新决策。应用退出恢复按非终态识别，不再遗漏新增搜索阶段；主动停止的轮次仍保持停止状态。

## 代码审查和清理

- 删除自然语言起草／重拟／修改地址的关键词路由和重复判断，保留显式 UI 行为及发送确认规则。
- 删除专用搜索规划请求、重复上下文节选和固定追问出口。
- 原生工具与文本适配器共用能力目录及 JSON 参数校验，删除无效参数静默变成空对象、未知工具继续返回成功式文本的旧逻辑。
- 缓存缺失、空值和损坏记录按未命中处理，不解析空字符串；成功的其他查询继续复用。
- 统一草稿检查点序列化；完成提交后移除动作和搜索中间缓存。
