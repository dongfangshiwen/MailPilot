# MailPilot 1.5.0（7）

## 聊天中确认并发送

直接对 Agent 说“帮我给 contact@example.com 写一封邮件，通知会议改到周五”，它会根据明确提供的地址填写目标收件人并起草。聊天中展示邮件确认卡片，包含发件人、收件人、抄送、密送、主题、完整纯文本正文及附件。检查后点击卡片的“确认发送”，手机直接连接配置的 SMTP 服务器；无需自建后端，也无需切换到独立发送页面。

也可在紧接确认卡片的一条消息中回复“确认发送”“同意发送”等明确短句。应用核对本次会话、最新消息、草稿版本和发件地址后发送；这不是模型可调用的工具。“不要发送”“改发给另一个地址”不属于确认指令。改变收件人、正文或继续其他对话后，旧确认失效。可以点击“修改邮件”，修改完成后按“在聊天中确认发送”展示新卡片。

模型只可检索、起草和修改本次对话的草稿。`revise_draft` 只更新指定字段，保留其他正文及已选附件。没有工具能力的模型在起草操作中使用结构化 JSON 草稿协议，解析失败不会发送。结构化草稿字段不直接作为聊天文本逐字显示；普通回答与可读思考仍按 SSE 实时输出。

提示词新增摘要、跨邮件比较、时间/金额/待办提取、催办、邀约、商务写作、翻译与润色指导。仅说“帮我写邮件”时先简短追问用途和内容，不把询问清单直接写成邮件正文。“写成邮件”现在请求模型整理正式邮件，普通说明不会再被无条件复制到编辑器。

发送记录仍按草稿 ID 和版本唯一保存，重复点击不能重复发送。SMTP 回执不确定时标记待核实，不自动重发；SMTP 接收成功不等于收件人已阅读。真实外部邮件仍须用户在应用内确认，本次开发测试未向外部收件人发送邮件。

## IMAP 同步与文件夹

发现的代码问题：文件夹发现依赖整页正文同步成功；每次无 SORT 的同步都会扫描全箱日期并重复解析已缓存正文。QQ 实际返回的“Sent Messages”“Deleted Messages”等名称也未完整映射中文。

改进：

- 文件夹发现独立执行，在点击收件箱选择器或手动刷新时更新；缓存列表随账号保存，失败时保留列表并显示重试入口。保留“仅显示未读”、搜索和账号切换。显示的是服务器通过 IMAP 提供的文件夹，网页专属分类未必通过 IMAP 开放。
- 启动只恢复本地缓存，不自动同步。后台频率默认关闭，已保存的用户配置继续保留。
- 无 SORT 时先核对 UID，再在服务器检索近期发送日期或接收日期，必要时逐步扩大到全部日期。候选按实际邮件日期排序；只有页面末项已在检索范围内才提前结束，并为日期时区边界保留两日余量。因此不会用最高 UID 代替最新日期，也不会静默排除导入的旧邮件。日期索引持久保存，已读正文复用，未读标记更新。
- 元数据批量读取，正文只读当前页。个别正文超限或格式异常会显示未完整读取，阻止把不完整正文用于分析，其他有效邮件继续保存。
- IPv4 / IPv6 地址错峰进行短 TCP 探测，选出可达地址后由实际 Socket 建立连接，探测连接全部关闭。使用自身文件描述符以兼容 Android 8.0 的 Conscrypt TLS；保留原始主机名的 TLS 身份验证及系统信任链，不固定 QQ IP，也不放宽证书校验。
- 同步进度与结果为浮动提示，更新时清除旧提示队列，不新增页面占位行。

协议参考：[Angus IMAP 配置](https://eclipse-ee4j.github.io/angus-mail/docs/api/org.eclipse.angus.mail/org/eclipse/angus/mail/imap/package-summary.html)、[IMAPFolder API](https://eclipse-ee4j.github.io/angus-mail/docs/api/org.eclipse.angus.mail/org/eclipse/angus/mail/imap/IMAPFolder.html)、[Angus SocketFetcher](https://github.com/eclipse-ee4j/angus-mail/blob/master/core/src/main/java/org/eclipse/angus/mail/util/SocketFetcher.java)。

## 实际 QQ 只读验证

2026-09-08，在当前开发机网络使用用户授权的 QQ 账号验证**实际应用的 MailRepositoryImpl / Angus Mail 代码**。凭据通过隐藏输入传给短生命周期测试进程；数据库仅在内存中建立。不下载附件，不发送 SMTP 测试邮件，不记录邮箱地址、授权码、主题或正文。

| 操作 | 实测 |
| --- | --- |
| 列出可选邮件文件夹 | 6 个，920 ms |
| 核对收件箱 | 992 封，QQ 未提供 SORT 能力 |
| 空缓存读取最新 10 封 | 4055 ms，11 封日期元数据，10 封完整正文 |
| 随后再次刷新 | 2336 ms，0 次正文下载，10 次缓存命中 |
| 只读检查 | 两次返回相同邮件 ID 与未读标记；正文未完整读取数为 0 |

同一网络此前 IPv6 连接超时、IPv4 TLS 约 0.12–0.14 秒；这是开发机网络的实测，不能据此断言物理手机的全部故障原因。速度随网络、邮箱数量及服务器缓存变化，上表不是性能保证。真实模型密钥未提供，模型功能使用本地模拟协议测试；SMTP 发送使用本地 GreenMail 收发核验，不以此替代真实收件人的送达验收。

## UI 与数据迁移

- 思考区移除固定高度，短文字随内容收缩；长文字仍有最大高度并可滚动，开始回答后自动折叠。
- 编辑页正文默认六行；添加附件和抄送/密送同行，Markdown 转换及删除收进右上角“更多邮件操作”。底部保留“在聊天中确认发送”主按钮。
- 新确认卡片优先定位到顶部，先看到目标地址；正文全部可查看和复制。支持系统字体缩放与深色模式。
- Room v4 → v5 自动迁移，新增文件夹、UID 日期索引、正文错误标记及不可变确认卡片快照；旧邮件、会话、草稿和凭据保留。历史确认中的正文供后续对话修改参考，摘要请求不会携带附件的本机文件路径。

自动化和安装包检查结果见 `docs/test-evidence/release150-*`；界面样例截图位于 `docs/screenshots/release150/`。APK 和完整交付包附同名 SHA-256 文件，发布签名继续沿用原密钥，私钥不进入源码包。
