# MailPilot 1.0.0：摘要预算修复、快速整理与会话隔离

内部构建 32，覆盖基线 31；正式版本仍为 **1.0.0**。设置页不显示构建号，保留发送确认提示。沿用发布签名，Room 保持 v9。

## 本次问题

只读检查设备的失败轮次：可用输入 24,576，材料摘要分配额度仅 512，完整候选估算 570，额外精简次数已为 2；五张图片命中缓存，没有重新上传。工具阶段为追求 60% 目标，再次缩小了材料摘要额度。失败由应用的局部预算校验产生，不能据此认定厂商上下文已满。

原来“继续整理”还会沿用耗尽的精简次数，相同预算下无法推进。代码审查另修复了预算变化时初始摘要分段布局变化、不能直接沿用原来源位置的问题。

## 修复与提速

- 区分建议长度和实际可用上限。95% 仍触发整理，60% 仍为目标；完整候选略长但最终请求可容纳时直接接受。所有实际请求仍通过统一输入校验，近期两轮完整对话不被硬截断。
- 新增工具结果后先整理工具交换，只有实际空间不足时再整理基础资料。移除为追求局部目标重复压缩材料的路径。
- 设置 → 偏好设置 → **上下文整理**，可选择“快速整理”。默认跟随当前思考模式；启用快速整理后，支持的 DeepSeek、百炼、火山接口只在整理任务关闭思考，正式回答与起草继续使用本轮思考设置。未知兼容接口保留当前模式，不猜测关闭参数。设置会持久化，并冻结在本轮快照中。
- 整理请求有独立输出预算和余量，不修改已保存模型的自动最大输出或自定义值。思考与正文共用额度、且无法确认思考预留时，保留原输出策略；不能为了缩短正文挤掉未知思考额度。截断结果仍按失败处理。
- 长资料按稳定内容片段生成独立摘要，近期 20 个有资料摘要的轮次可复用。缓存绑定账号、会话、模型设置及内容指纹，不绑定当前问题；本轮重新绑定来源编号。追加资料、修改片段时只处理未命中的内容，真正需要时才合并片段摘要。
- 原文保留在本轮授权资料，模型可通过既有 `read_evidence` 读取遗漏范围。历史摘要仍按先后顺序整理，保留修正关系；缓存不新增发送授权。
- 逐批保存有效结果。网络错误、取消不会消耗“摘要过长”的成功精简次数；额外完成的精简仍最多两次，不进行无限自动重试。实际超限且不可直接恢复时隐藏无效的“继续整理”，保留调整资料、查看预算和修改配置。
- 同内容预算变化可复用完整候选；分段布局变化会重新核对来源位置，防止跳过内容。只保存完整有效摘要，合并失败不会删除已经完成的片段。

## 每个会话独立上下文

现有实现并不是跨会话拼接历史：历史查询、正式摘要、图片分析、动作检查点均按会话隔离。模型配置可以共用，但每个请求独立计算上下文占用，其他会话的聊天量不会扣入本会话。

新增资料摘要同时校验账号、会话、请求快照和内容指纹。测试在两个会话放入不同历史与摘要标记，逐个检查完整模型请求；另一个会话不会命中资料摘要缓存。跨会话历史或错误快照在发请求之前被拒绝。

## 审查与诊断

清理了过紧的局部摘要上限、工具阶段提前压缩基础资料的旧分支和重复保存的叶片工作状态。缓存查询改为逐轮读取，避免一次加载多份完整附件／工具快照；每轮最多 128 条片段缓存，并限制字典体积。删除会话时随原轮次级联清除，邮箱原件与独立草稿不受影响。

每轮最多保留 40 条成功整理请求的诊断样本：建议长度、实际空间、估算输入／摘要长度、思考字符数、首正文时间、生成耗时及精简次数；另记录分块缓存命中和生成数。样本不记录正文、思考文本、提示词或密钥。时间和 Token 估算不能代替厂商真实计费或性能数据。

## 验证和使用

Flutter Analyze、Flutter 测试、原生测试、Lint、API 36 设备测试及覆盖安装的数据核对结果见 [验证记录](test-evidence/build32/validation.json)。覆盖 570/512 小幅超标、两次精简耗尽、连接失败恢复、预算变更、来源重绑定、跨账号／会话隔离、三家厂商请求参数、完整工具循环和五图缓存复用。

设备复用 `MailPilot_API36`。所有本轮模型与搜索响应为合成测试；没有调用真实厂商、邮箱或 SMTP。设备计时记录含固定模拟延迟，只用于检查缓存减少请求，不能解释为真实厂商提速倍数。真实模型的事实保留质量和端到端速度仍需用相同样例验收。

安装新版后，可先对原失败消息点击“继续整理”。若实际输入仍无法容纳，应调整本轮资料或模型配置，不盲目增大未经核实的套餐额度。要减少整理阶段的思考等待，可开启“快速整理”。
