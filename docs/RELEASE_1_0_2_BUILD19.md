# MailPilot 1.0.2（19）

本次按用户要求继续使用正式版本 1.0.2，内部构建号从 18 递增为 19，沿用发布签名。

## 版本栏间距

- 将 `‹ 1 / 3 ›` 数字区域的最小宽度由 48 dp 收为 32 dp，左右箭头向数字靠拢。
- 每个箭头仍保留独立的 48 × 48 dp 点击区域；灰色文字、禁用状态和版本切换行为保持一致。
- 大字体下数字可自然扩展；用户点击气泡仍打开底部操作面板。

## 验证

- Flutter 静态分析通过；现有版本切换和编辑回归共 38 项通过，覆盖 320／360／412 dp、深浅色及 1.0／1.6／2.0 字体。
- API 36 编辑、取消、重发及多版本切换流程通过（1 项流程，另含清理回调）。[第三版截图](screenshots/release102-r19/chat102-inline-third.png) / [第二版截图](screenshots/release102-r19/chat102-inline-second.png) 使用明确标注的样例数据，未调用真实模型。
- 从原签名 1.0.2（18）覆盖安装至 1.0.2（19）通过；应用 UID 和首次安装时间保持一致，正常启动，无崩溃。验证基线为临时模拟器的空数据环境，不代表真实用户账号数据迁移实测。
- APK 发布签名与旧版一致，版本信息正确，16 KB ZIP 对齐通过。首次设备测试遇到 ADB／VM Service 短暂断开，重连后重试通过；两次日志分别保留在 `docs/test-evidence/release102-r19-device*`。
- 已清理本轮临时设备 MailPilot_102_R19_Test36，保留日常 MailPilot_API36 及已有系统镜像。
- 本轮只调整版本栏布局，未重跑原生业务与厂商联网测试；上一构建结果见 [构建 18](RELEASE_1_0_2_BUILD18.md)，不作为本轮重新实测结果。

## 安装与构建

直接安装 `MailPilot-1.0.2-flutter-release.apk` 覆盖旧版，请勿先卸载。设置页应显示 1.0.2（19）。使用 `scripts/Build.ps1 -Mode Release` 生成 APK，`scripts/Package-Delivery.ps1` 生成源码及交付包。签名材料不进入源码包，备份方式沿用项目签名说明。
