# 构建 33 代码审查

审查范围：Agent 工具循环、搜索并发与缓存、快速整理迁移、资料摘要复用、流式事件、思考区、重试与恢复、诊断落盘、Windows 测试／发布脚本。不是对所有第三方依赖的完整安全审计。

## 已修复

1. 工具结果预算只考虑正文，遗漏标题、链接和协议开销。现在按最终展示整体计量，并保留来源和读取范围。
2. 重复对完整搜索交换调用模型整理。新增可复用摘录和已经覆盖位置，只在本地精简后仍达到阈值时生成摘要。
3. 两条独立查询串行阻塞。并发上限为二，成功项单独落盘，按原顺序合并；失败只重试缺失项。
4. 快速整理设置进入已完成动作及资料缓存的身份。已从内容复用标识分离，兼容旧快速整理检查点，保留原搜索范围键；账号、会话、模型、资料约束仍校验。
5. 思考每轮完成折叠、下一轮重新展开。改为整轮结束策略，手动展开与滚动优先，思考内容按请求追加。
6. 重试清空旧思考。新增有界尝试历史；停止后立刻重试等待旧写入结束，并从数据库读取最新检查点。
7. 周期保存当前消息导致完整历史重新跨平台传输。活动行持久化不再被识别为结构变化；增量帧使用订阅标识和顺序去重。
8. 最后一秒内完成的状态可能未落盘。成功／失败立即保存最终思考和诊断，最终记录更新后退出流式展示。
9. 触及八轮工具上限被标作正常回答。现在返回类型化失败，保留原草稿和可恢复记录。
10. Windows 设备测试脚本沿用默认 `flutter drive`，会卸载日常应用。本轮由此发生数据丢失，尚未完整恢复。脚本现统一采用隔离包名、安装前包名校验和 `--keep-app-running`；发布构建拒绝隔离测试环境。详见发布说明中的事故记录。

## 保留的边界

- 不新增模型 SMTP 发送工具；草稿确认、版本检查及发送状态保护继续执行。
- 取消、失败和重启不把未完成输出保存为成功草稿或有效图片观察。
- 摘录引用仅解析本轮已授权来源，缓存不能越过账号／会话范围或新增发送授权。
- 诊断只持久化时间、计数、型号、主机、请求标识、结束原因、异常类型；不记录完整提示词、邮件正文、图片或密钥。
- Room 保持 v9，旧思考文本仍可显示；旧摘要、来源和发送记录继续兼容。
- 用户有意保留的模型配置、自定义额度和发送确认提示未移除。旧接口兼容回调仍被既有调用方使用，不按“冗余”随意删除。
