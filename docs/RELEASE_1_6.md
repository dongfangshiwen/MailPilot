# MailPilot 1.6.0（8）

## 连续聊天与资料快照

“×”只清空当前选择，不新建会话。重选邮件、附件或 PDF 页码，同一账号内切换文件夹，都保留当前聊天和历史分析；主动点击新会话才重新开始。不同账号的邮件聊天继续隔离。

每次提问保存独立资料快照。生成中换选只影响下一次问题，不改变当前请求。模型可以参考已有回答和历史摘要，但不重新读取已取消选择的原文或附件；需要核对旧原文时应重新选择。新来源编号包含轮次，例如 `[T3:S1]`，旧会话的 `[S1]` 链接仍按原消息打开。

## 手动触发、后台增量同步

“我的邮件”右上角同步图标或下拉刷新启动当前账号的任务；初次每文件夹缓存最新 50 封，当前文件夹和收件箱优先，随后处理其他 IMAP 文件夹。邮件头与附件清单先出现，再逐步补齐正文，未完成正文明确显示“正文待同步”。附件文件仍按需下载。

启动、打开文件夹选择器、切换文件夹不创建同步任务。文件夹选择器右上角按钮只刷新文件夹名称。未读筛选只用本地数据；输入关键词提交时另行异步搜索服务器。用户之前开启的定时同步继续有效；已经排队但被系统中断的任务由 WorkManager 恢复。

同步使用账号唯一 WorkManager 任务，不占用全局忙碌状态。同步时仍可浏览、聊天、选资料和编辑；点击转动的同步图标可取消。网络不可用时排队等待，重复点击不会创建并发任务。某个文件夹或正文失败时保留已完成内容，并在结束提示中说明，可手动重试。

Android 8 的设备回归还发现：能直连 QQ 的网络可能未通过系统连通性探测，导致 WorkManager 的 CONNECTED 条件一直不满足。已改为任务内部检查实际网络能力，离线时退避重试，邮件连接结果由邮箱服务器决定；不会依赖系统探测站点是否可达。原因可对照 [AndroidX 的网络约束实现](https://android.googlesource.com/platform/frameworks/support/%2B/refs/heads/androidx-work-release%5E1..refs/heads/androidx-work-release/)。

初次按邮件日期选出最新 50 封；后续通过每个文件夹的 UIDVALIDITY 和已提交 UID 游标读取新增邮件，每批最多 50 封，新增超过 50 封继续分批处理。已缓存正文不重复下载，批量核对缓存 UID 的未读和删除状态。“加载更多”读取更早的 50 封，既有缓存保留。系统限制后台运行时长，取消或退出不会丢失已提交的元数据与正文，未完成部分下次继续。

## 草稿重拟、删除及语言

草稿列表和聊天确认卡片的“草稿操作”菜单提供重新拟写和删除。删除需确认，只删除本地草稿；历史记录保留，旧卡片不能再发送。

对 Agent 说“重新拟一份”“更正式一点”“改成英文”，或点击“让助手重新拟写”，会更新当前草稿。默认保留发件人、目标地址、抄送/密送和附件，生成完整结果后才保存新版本。失败、取消、旧版本冲突或草稿已删除时不覆盖原稿；新卡片需要重新确认。已发送邮件重新起草会创建独立新草稿，发送中和待核实状态禁止覆盖。

在编辑页手动修改内容后，需先保存，才能从该页发起重新拟写，避免未保存的地址或正文被忽略。

用户明确指定语言优先。回复跟随原邮件主要正文，新邮件跟随用户提供内容，重拟沿用当前草稿语言；判断时忽略引用历史、签名和邮箱域名。确实无法确定时先询问。正式主题和正文按目标语言起草，聊天解释默认中文。工具模型与无工具模型均支持结构化重拟。

邮件分析默认解释主要内容、事实和对方要求，不主动做风险评级、诈骗判断或安全分析。用户明确要求时再讨论这些问题。资料访问检查和用户确认发送机制继续保留。
