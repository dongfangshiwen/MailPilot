# MailPilot 1.0.0（36）：DSML 工具协议兼容与显示修复

核实与测试日期：2026-09-10 至 2026-09-11。显示版本继续为 **1.0.0**，设置页不显示内部构建号，Room 保持 v9。

## 根因与适用范围

用户提供的 DSML 中包含 `calls`、`invoke`、`parameter`，参数是两条搜索查询。旧版仅识别 Seed 和应用 JSON 操作；DSML 未进入工具规范化，随后被当作普通回答显示。这是应用侧可以复现的兼容缺口，不是“搜索已经执行，只是显示难看”。没有取得该次请求的完整服务端响应，因此不能据复制文本断定是哪一层服务把工具字段放入了正文。

DeepSeek 的[公开编码说明](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro/blob/main/encoding/README.md)定义了 DSML 的调用与类型化参数；官方 HTTP API 的[工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)仍使用结构化工具字段。应用继续优先使用标准工具字段，兼容层仅处理模型泄漏到 assistant 正文中的有限工具封装。

标准 `tool_calls`、旧 `function_calls` 和本次观测的 `calls` 通过同一份格式描述进入解析器。支持完整匹配的单／双竖线标记、ASCII／全角形式、控制标记间空格或不换行空格，以及控制字符与名称中的 Markdown 转义。这些是语法适配；没有按 GitHub、OpenAI、公司名称或问题句子添加执行分支。

## 优化前后

| 方面 | 优化前 | 优化后 |
|---|---|---|
| DSML 完整操作 | 被当作普通文本，搜索未执行 | 统一转换为工具调用，再由工具注册表校验并执行 |
| 流式输出 | 可能逐片显示内部协议 | 在控制标记尚未完整到达时保留片段，正文仅显示可见内容 |
| 思考增量 | 原样显示，协议可能进入过程区 | 使用同一协议识别器过滤显示；原始模型消息保留给协议续接，思考文本本身不执行工具 |
| 旧消息 | 继续显示未处理的控制标记 | 仅清理显示并提示原调用未处理，不自动搜索，不伪造已完成状态 |
| 参数解析 | Seed 使用另一套宽松 JSON 解析与深度检查 | 原生、JSON 操作及内嵌参数共用严格 JSON 读取，移除重复分支 |
| 重复格式 | 已支持 Seed 与原生字段一致性校验 | DSML 同样复用校验，相同操作只执行一次，冲突则拒绝 |
| 格式失败 | DSML 可能绕过错误分类变为普通回答 | 未闭合、未知封装或无效参数进入稳定的操作格式错误；已有资料沿用预留收尾阶段 |

## 审查与边界

- `InlineToolCalls` 用格式描述区分封装、函数和参数标签，共用字符扫描、完整性检查、流式隐藏与历史显示清理，没有复制一个 DSML 执行器。
- `AgentActions` 仍是唯一的工具权限及参数校验入口。兼容格式只能进入当前可用的只读工具；没有新增 SMTP 工具，也不能通过 DSML 绕过草稿修改或发送确认。
- 只有 assistant 正文中的完整末尾封装才能被规范化。行内代码、代码围栏、引用块及 JSON 字符串中的示例不作为操作。用户消息和历史展示不触发工具执行。
- 整组调用先全部校验，最多四个操作；后一个残缺或参数错误时不会先执行前一个。拒绝重复字段、重复参数、尾随 JSON 值、过深嵌套、异常属性及超大封装，不补括号、不猜测缺失参数。
- 只解码控制字符和标识符中的已支持转义；查询文本内的反斜杠、引号和 Unicode 保持原值。没有 HTML 实体、DTD 或外部实体解析。
- Android 的严格 `JsonReader` 需要对象／数组根节点。对独立标量使用单值数组读取容器，并校验完整结束，保持严格模式；数字、布尔值、null 不因此变成字符串。旧 Seed 数字参数回归已覆盖。
- 保留请求次数限制、只读回执复用、会话和账号隔离、原始资料及发送状态。没有增加模型修复请求，也没有新增自动重试循环。
- 本地格式错误使用稳定的阶段、协议类别和校验结果，不记录参数正文或凭据。

## API36 与真实接口

使用已有 MailPilot_API36 / emulator-5556，API 36。设备上的固定 DSML 重放覆盖有工具／无工具模式、普通空格／不换行空格，共四种组合；每组两次生成、两条搜索查询，正文及思考无协议泄漏，零草稿。模型和搜索返回为固定样例，不能当作厂商性能数据。

当前设备只有配置好的 `doubao-seed-evolving`，以真实搜索服务检索公开 GitHub Trending 信息。最终运行 **56.003 秒，3 次模型请求、2 条搜索查询、8 个来源、0 次网页原文读取、完整回答、0 草稿**。这次返回规范 JSON 工具调用，没有复现 DSML，故 DSML 的成功执行由上述固定重放和 HTTP 分片测试证明；不声称已完成 DeepSeek 真实接口验证，也不把 8 个搜索来源描述成读过 8 个网页。详见[真实运行元数据](test-evidence/build36/live-search.json)与[最终设备测试：2 项通过](test-evidence/build36/api36-tests.log)。

另一次真实调用曾在匹配工具结束封装时失败，调用未执行；当时只有异常栈，无法确认是模型省略了结束标签，还是另一种尚未覆盖的变体。已保留[该次失败](test-evidence/build36/api36-format-failed.log)，并扩展通用设备测试记录控制标签名称和协议形态（不记录参数、正文或凭据）。增加记录后的同条件手动重试返回正常 JSON 并完成。后一次成功不替代前一次失败，也不证明所有不完整格式都已消除。
