# 思考区图标与工具标记泄漏：修复及代码审查

日期：2026-09-10。基于 1.0.0 构建 33 的后续源码修复；本轮没有重新发布正式 APK，也没有改变版本号、数据库版本或签名。

## 问题与原因

用户反馈两项问题：思考区不需要“回到思考末尾”的可见文字；回答中出现 `seed:tool_call`、`function`、`parameter` 等内部调用标记。

代码中可复现的原因是：`AgentActions.normalize` 原先只识别标准 `tool_calls` 和应用约定的 `mailpilot_action` JSON，流式显示也只拦截可能的 JSON。Seed 文本调用出现在 `content` 时，会被当作普通回答，不进入搜索流程。这是应用兼容处理的缺口；没有取得用户失败请求的原始服务端响应，因此不能据此确认是厂商、代理还是某次模型生成造成了格式泄漏。

## 已实施的修复

| 项目 | 修改后行为 |
|---|---|
| 思考区末尾入口 | 只显示向下箭头，最小点击区域 48 × 48 dp；无可见文字、无文字 Tooltip，保留读屏标签 |
| 流式工具标记 | 跨片段保留未完整接收的控制标记，不将半个标记和参数显示到气泡；前面的正常说明可继续显示 |
| 完整文本调用 | 转换为现有工具决定，经同一能力和参数校验后执行；执行结果返回模型，再生成正式回答 |
| Markdown 转义 | 支持控制标记及名称中的转义形式；不对搜索参数整体做替换，避免改变实际查询内容 |
| 标准调用与文本重复 | 两种表示完全一致时执行一次；内容冲突时返回明确错误，不选择其中一种静默执行 |
| 残缺、未知或不合法调用 | 返回 `action_format`，保留已显示说明和原有恢复流程，不当作成功回答，也不自动请求模型修复格式 |
| 历史回答 | 展示可读提示，说明不能据旧标记确认检索完成；打开历史不会补执行工具，也不改写原始聊天记录 |

## 审查发现及冗余清理

1. **同一工具决定重复校验。** 新响应和恢复中的决定现在分别在入口校验一次，移除工具循环后面的重复校验；恢复仍检查当前能力范围。
2. **协议识别规则容易分叉。** 新增 `InlineToolCalls`，流式过滤、完成时解析和旧记录展示共用控制标记识别；删除不再使用的中间标记对象。
3. **参数和常量重复构造。** 控制标记、属性、实体检测及只读动作集合集中定义；一组调用的标识摘要只计算一次。
4. **示例文字误执行风险。** Markdown 代码块、行内代码、引用行和 JSON 字符串中的示例不作为操作执行；用户历史内容保持原文，不套用助手回答的展示过滤。
5. **兼容格式扩大操作权限的风险。** 文本兼容入口只允许 `web_search`、`read_evidence`、`search_emails`，并且必须是本轮已开放的动作。它不能创建、修改或发送邮件；现有正式 JSON／原生草稿流程继续执行原有规则。
6. **异常参数造成解析失控的风险。** 最多四个动作、每个动作最多 32 个参数、控制内容最多 128,000 字符、JSON 嵌套最多 16 层；重复参数、未知属性及错误类型被拒绝。
7. **XML 解析风险。** 使用受限控制标记解析，不运行函数名、不执行代码、不加载 DTD 或外部实体；没有新增通用 XML 解释器。
8. **工具类型未校验。** 显式提供的工具类型必须为 `function`，未知类型不会进入已有函数执行分支。

保留现有标准 `tool_calls`、JSON 动作适配器及旧检查点兼容。这些仍有调用方，不属于可以直接删除的旧逻辑。搜索仍经过原有隐私过滤，资料读取仍受本轮来源和账号／会话范围约束。

## 验证记录

- Flutter 全量 365 项通过；静态分析无问题。
- 原生全量 230 项：228 通过、2 条件跳过、0 失败；Lint 0 错误，13 条原有警告。
- 思考区回归覆盖 320／360／412 dp、深浅主题、字体 1.0／1.6／2.0，验证没有可见文字、点击区域不小于 48 dp、点击后实际到达末尾。
- 原生回归覆盖完整／残缺／转义标记、逐字符流式边界、重复与冲突、超限参数、代码示例、能力关闭、禁止的写操作及历史展示。
- 完整 Agent 回归覆盖原生工具和文字适配两种模式：先执行公开搜索，再生成最终回答；未生成草稿。
- 本地 HTTP SSE 服务将控制标记按三个字符分片，以 `finish_reason=stop` 结束且不发送 `[DONE]`。完整 Agent 路径共两次模型请求、一次搜索调用，第二次请求包含工具结果，正文和后续请求均没有泄漏标记。
- 在现有 API36 的隔离包 `app.mailpilot.validation` 上执行 Profile 界面测试，深浅主题均通过。脚本使用 `--keep-app-running`，结束后日常包与测试包均仍安装；没有卸载日常应用。

最终原生数量、Lint 统计和日志见 [本轮证据目录](test-evidence/tool-envelope-fix/)。截图为真实思考组件的独立测试页面：[深色](screenshots/build33/reasoning-icon-dark.png)、[浅色](screenshots/build33/reasoning-icon-light.png)，不是整套产品页面截图。

本轮使用合成数据和本地服务，没有重跑真实厂商接口，不能声称厂商今后不会再输出异常格式，也不承诺兼容所有 XML 或第三方工具协议。
