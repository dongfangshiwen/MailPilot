# MailPilot 1.0.0（29）· 流式显示、引述返回与默认最大输出

正式版本继续为 1.0.0，沿用原发布签名，内部构建号递增至 29，Room 保持 v9。设置页仅显示版本和“每次发送邮件，都由你确认。”，不显示构建号。

## 修复内容

原先原生端每次流式刷新会重新编码整页数据，包含历史、来源和模型目录；思考区逐段跳到末尾，主聊天也不断重启滚动动画。现在首次与结构变化发送完整快照，连续思考和正文发送带序号及会话校验的增量，JSON 编码在后台线程完成。历史 Markdown 未变时复用渲染组件；实际收到的文字突发片段最多用 80 ms 展开，不模拟网络内容，结束、取消及减少动画设置直接显示已收全文。滚动逐帧追随实际内容高度，手动上翻后暂停跟随，点击向下箭头恢复。

打开引述时保留聊天页面、滚动控制器、输入内容、编辑与版本选择；隐藏页面停止动画并退出焦点。通过页内返回或系统返回退出引述，回到原来的阅读位置，不重新定位至最新回答。

## 默认最大输出

新模型默认选择“跟随型号最大值”。官方接口的已知型号不再受应用固定 32,768 输出校验限制。旧配置中仍为默认 4,096 的已核实型号使用自动模式；其他自定义值保留。用户可切换“自定义”，包括明确保存 4,096；保存后的选择通过 DataStore 保留。自动模式以既有输出列的 0 标记保存，发送前转换为实际正数，0 不会传给模型。

主模型、起草与视觉助手共用输出策略，自动创建的视觉助手按自身型号计算，避免继承文字主模型额度。选择最大值只放宽上限，不要求模型写满。自动模式先保留基本回答空间以规划输入，最终请求按完整图文、工具和历史的估算占用计算剩余空间，取厂商最大输出与剩余额度的较小值。自定义输出继续参与完整预算预留，超限不发送请求。

本轮重新查阅 [DeepSeek 模型规格](https://api-docs.deepseek.com/quick_start/pricing/) 及[官方配置示例](https://api-docs.deepseek.com/quick_start/agent_integrations/pi_mono/)，采用示例中的十进制 1,000,000 上下文／384,000 输出，纠正旧目录的二进制换算。视觉型号与文字 V4 型号共用规格页列出的 384K 输出上限。[千问 3.8 Max](https://help.aliyun.com/zh/model-studio/qwen3-8-max) 为 131,072 输出，[千问 VL Flash](https://help.aliyun.com/zh/model-studio/qwen3-vl-flash) 为 32,768；两者在该规格页的思考／非思考模式下输出上限相同。

其余已核实型号沿用内置目录和原核实日期；火山标准接口与套餐接口继续区分。未知型号、代理和未核实的火山套餐接口不能推断最大值，自动模式明确提示暂用 4,096，可自行设置。目录不在启动时联网测试。

达到厂商实际上限、输出截断或断流仍保留未完成状态，不会伪装成完整结果。此次提高额度不能保证任意长文档都不再截断。

## 审查与清理

- 移除全状态逐片段编码循环和未使用的事件 sink；新增订阅正确取消旧采样任务。
- 移除思考区逐片段跳滚动、正文反复重启动画和计时器反复创建逻辑。
- 复用同一输出策略，删除固定 32,768 上限；检查自动值在请求、摘要预算、视觉助手和思考预算校验中的兼容性。
- 增量帧验证账号、会话、响应及序号，错序不能拼接到其他回答；取消与完成保留全部已接收内容。
- 保留旧记录解析、部分回答保护、用户发送确认及 SMTP 隔离，不清理有效用户资料。
