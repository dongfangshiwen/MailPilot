# MailPilot 1.0.0：完整请求预算与可恢复整理

内部构建号 31，覆盖基线 30；正式版本继续为 **1.0.0**，设置页不显示构建号。沿用原签名，Room 保持 v9。

## 本次原因与修复

只读设备诊断显示：配置上下文 32,768，扣除输出和思考预留后可用输入 24,576；本地整理请求估算 27,541。两条搜索查询已完成，五张图片命中缓存、没有重新上传。失败发生在下一批整理的本地检查，并非 SMTP 或厂商报告上下文已满。

旧实现按原始文本分块，再将旧摘要、工具 JSON 和消息重复包装，转义膨胀后才发现超限。本版调整为共享的请求准备、授权来源视图和可恢复整理三个环节：

- `PreparedModelRequest` 冻结最终消息与工具定义，共用 `ContextBudgetPlanner` v6 校验。逻辑文本与 HTTP JSON/Base64 字节分别计量；未知图片估算仍不单独阻止图文请求，32 MiB 请求体等限制保留。
- `CompressionPacker` 使用系统提示、旧摘要和新片段的完整结构确定可容纳范围；在本地缩小片段，优先按换行及 Unicode 边界切分，不用失败的模型调用试探大小。
- 搜索全文留在本轮来源和动作检查点。模型先看到各来源的摘录、已覆盖范围及下一位置，需要更多内容时通过 `read_evidence` 读取。它不能访问任意路径、未授权邮件或其他会话。原生工具保留调用／结果配对；文字模型不再接收多层包装的工具消息 JSON。
- 每个有效批次保存来源块和字符位置。完整但过长的候选单独保存，精简中断后可继续。单次最多推进 24 批；额外精简请求最多两次，按整个轮次累计。
- 95% 触发整理、60% 为目标。最近两轮完整对话确实需要更多空间但完整请求仍符合输入预算时，可以继续回答。真正无法容纳的内容仍需用户调整，不能保证任意资料量都一次成功。
- 动作恢复身份使用原始输入及来源，避免整理后的文字变化导致成功动作失效。图片复用、手动重试、最新草稿确认与发送状态保护继续生效。

## 界面与诊断

预算错误提供“查看预算”“调整资料后重试”和“修改配置”；整理失败提供“继续整理”。预算抽屉展示输入估算、可用额度、上下文配置以及输出／思考预留，注明本地估算与厂商计量不同。整理进度只在运行期间显示。

新失败只记录对应请求的诊断，避免混入上一次成功请求的结束原因和耗时。日志不记录正文、查询词、图片或凭据。

## 交付与清理

`artifacts/MailPilot-1.0.0-flutter-release.apk` 为正式签名包；源码和交付 ZIP 包含 Windows 构建脚本、中文说明、测试及截图，不包含签名私钥和本地配置。请直接覆盖安装，不先卸载。

本轮临时数据库副本和原始合成图片已由测试清理；测试运行器已移除，交付后清理本地生成的构建缓存。保留共享预览缓存、日常模拟器、既有系统镜像、用户资料及有效视觉缓存。未创建临时模拟器。

设计依据沿用 [Deep Agents 上下文管理](https://docs.langchain.com/oss/python/deepagents/context-engineering) 的本地全文与按需引用思路，以及 [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence) 的分阶段检查点思路；在现有 Android 服务内实现，没有引入后端框架。详细诊断与设计见 [设计记录](CONTEXT_BUDGET_RECOVERY_DESIGN.md)。
