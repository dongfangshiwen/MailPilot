# MailPilot 1.0.0（34）：优化前后对比

核实日期：2026-09-10。设置页仅显示 1.0.0，内部构建号 34；Room 仍为 v9。

## 根因与处理

| 项目 | 构建 33 | 构建 34 |
|---|---|---|
| 循环结束 | 八轮后抛错，已有资料不能成为正式回答 | 最多七轮收集，预留一次无工具的最终回答 |
| 重复操作 | 只比较完整参数；直接报错 | 复用只读结果，按来源内容版本和读取范围判断进展 |
| 换关键词但结果相同 | 可以持续循环 | 连续两轮没有新增资料后回答已有结果 |
| 耗尽轮次重试 | 恢复轮次 8，可能不发请求就再次失败 | 直接恢复最终回答；“继续检索”另开有限收集阶段 |
| 来源阅读 | 仅能读取搜索服务返回的摘录 | 可按来源编号获取公开网页正文，明确记录是否实际取得正文 |
| 工具上下文 | 每轮可能重新携带多个完整摘录并调用整理模型 | 旧工具记录保留回执，来源索引共享一次，最新工具结果保留；输出视图按剩余预算分配 |
| 并发中断 | 成功搜索保留；没有网页读取阶段 | 搜索成功项保留；网页每个成功项立即保存，取消后只补未完成项 |
| 过程区 | 思考和工具状态分开 | 单一可折叠时间线，保留用户展开和阅读位置，按钮仅显示箭头 |

以上是应用代码中确认的机制；没有取得用户截图那次运行的完整八次调用序列，因此不能断言每一轮具体执行了什么。

## 实测方法

复用 `MailPilot_API36`（本轮序列号 emulator-5556），使用设备上已配置的 `doubao-seed-evolving` 及真实搜索服务。临时 Room 数据库内放入合成邮件、五张 256×160 图片和四组历史问答。模型和搜索凭据在原应用进程中使用，未导出明文；测试邮箱没有 SMTP 凭据。

每版分别测试首次分析、复用图片的追问，以及请求发出前模拟失败后的手动重试。思考启用、快速整理启用；模型原有上下文与输出配置保持一致。测试记录元数据，不记录模型正文、图片或凭据。

构建 33 的首次样例成功完成，耗时 74.745 秒、8 次模型请求、4 条搜索查询。它不构成截图故障的直接复现。原始记录见 `test-evidence/build34/live-baseline33.json`。

开发中第一次实测为 136.232 秒、10 次模型请求、6 条查询，实际读取两页网页。新增阅读和重复工具上下文使首轮更慢；据此继续修改为共享来源索引与按剩余空间分配工具视图。保留该次原始记录 `live-current34.json`，不将它伪装成提速结果。

最终首次分析为 **41.556 秒、4 次模型请求、2 条查询**，没有额外的工具结果整理请求。追问为 39.918 秒（旧版 34.044 秒），失败重试为 12.336 秒（旧版 24.323 秒）；不能宣称所有情况更快。完整数据、回归结果和交付校验见 [发布与测试说明](RELEASE_1_0_0_BUILD_34.md)。真实服务结果会变化，单次对照不是统计基准，也不能用于宣称复制 DeepSeek APK 的内部流程或速度。

## 架构与安全审查

- `ResearchProgress` 只记录可核验的资料变化、已读范围、回执和阶段；没有增加模型规划／评判调用，没有硬编码特定公司或产品关键词。
- `WebReadWorkflow` 独立管理八页上限、两路并发和成功检查点。`PublicWebReader` 使用无凭据客户端，对连接 DNS、字面 IP 及每次重定向验证公网范围。连接 10 秒、总请求 30 秒、最多三次重定向，解压后响应不超过 2 MiB；不执行网页脚本。
- 最终回答通过空动作注册表校验，原生工具请求设置 `tool_choice=none`。异常工具协议不会执行，也不会直接显示给用户。
- 网页结果标记为结构化 `retrieval=webpage`，旧数据缺省为空；缓存不依赖展示文案。轮次、历史、资料范围继续校验账号与会话。
- 大网页原文存入会话内文件，轮次 JSON 只保存内容指纹和小段预览，避免多页正文反复写进同一数据库行。恢复校验内容指纹与所属会话，文件失效时退回摘录并允许重读；不会将预览当作完整原文。
- 仅完整验证后的草稿候选走原事务与版本检查；工具循环没有 SMTP 工具。最终回答网络失败仍保留检查点，不将失败结果当作完成。
- 工具时间线以请求与事件标识去重、排序；停止后保留已完成思考，不补造模型思考或“已浏览”数量。
