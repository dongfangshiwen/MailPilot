# MailPilot 1.0.0（39）：网页读取复查修复

本轮修复[构建 38 代码复查](CODE_REVIEW_BUILD_38.md)中四项已复现的问题。发布版本保持 1.0.0，内部构建号递增为 39，设置页不显示构建号，保留发送确认提示；Room 保持 v9。

## 优化前后

| 问题 | 构建 38 | 构建 39 |
|---|---|---|
| 页面请求权限 | 同源 JSON／表单编码 POST 可由兼容层自动代发，不能证明只读 | 原生传输只接受 GET；移除 POST 封装、类型推断、正文解码和代发。需要提交请求的页面返回 `interaction_required` |
| 加载提示误判 | 初始 HTML 达 40 字，或渲染文字达 80 字就可能判为完整 | 按可见忙碌状态、DOM 就绪、未完成 fetch／XHR、资源失败、文字稳定及正文变化判断；没有字符数“完整”阈值 |
| 累计体积限制 | 完整下载资源后才累计，超额后仍发出新请求 | 每次读取响应体前预留共享额度；并发读取共同计入上限，耗尽后停止新连接并取消其余连接 |
| 异常 Content-Type | POST 媒体类型解析在错误边界之外，可抛出异常 | 删除该 POST 路径；地址、请求构建、响应 MIME 和字符集解析统一处于传输错误边界内 |
| 旧缓存与恢复 | 已误判完整的旧网页可能持续复用 | 网页读取策略 v3；旧记录保留为未核实片段，读取后才取得当前版本完整缓存。JSON 缺省兼容，数据库不迁移 |
| 重试状态 | 非 `limited_content` 的异常文字有进入完整缓存的风险 | 除 `complete`／有效 `cached` 外的文字统一是部分片段，最多保留 4000 字；同次尝试复用失败片段不增加真实读取次数 |

## 通用实现与审查

`WebContentPolicy` 分析文档状态，`AndroidWebRenderer` 观察动态页面，`WebRenderTransport` 限制请求权限，`WebBodyBudget` 管理并发资源额度。没有按具体域名、公司名称、发票内容或“取消”等接口名称设置放行规则。脚本中的观测器不改写请求方法、地址或正文，也不授予操作权限。

每次渲染的应用响应体读取上限为累计解压后 12 MiB，单资源 2 MiB，最多 48 次资源连接；初始 HTML 另外受已有 2 MiB 限制。额度统计包含随后被判为失败的已读正文。这里限制的是应用消费的解压后正文，不是底层 socket、TLS 或网络缓冲器的物理字节数。已知超大 Content-Length 直接拒绝；未知长度恰好达到单资源上限却未确认 EOF 时保守返回受限状态。

保留实际解析 IP、公网地址、重定向、凭据隔离、CSP、禁用 WebView 直接联网、文件和表单操作等约束。缓存按账号／会话隔离；旧网页回执的键加入策略版本，旧工具展示和摘要也按新来源状态更新，保留搜索结果、草稿候选和已完成操作，不因升级重放写操作。

已删除自动 POST 兼容脚本及原生解码／提交分支、40／80 字完整性判断及旧的事后额度累计逻辑。复查了失败／取消清理、并发预留归还、旧缓存恢复、引用编号及真实请求计数。引用选区与布局沿用构建 38 修复。

## 访问边界

部分网站以 POST 获取普通数据，但同源或 JSON 类型不足以证明它没有写入效果；本版不再自动代发。需要这类请求、登录、验证码、点击或文件下载的页面会明确提示限制，保留实际已取得的片段。此变更可能减少某些网站的自动读取范围，是修复权限缺陷后的实际兼容边界。

动态页面没有统一的“所有内容已加载”协议。完整状态表示在有界观测期间取得符合当前策略的可见正文，不证明隐藏面板、后续交互、图片或文件内容已经读取。没有正文变化、资源失败、持续加载或只有操作入口时不作为完整缓存。用户发票明细此前未读取，本轮不能宣称已解决该站点的文件／图片内容提取。

| 真实 doubao-seed-evolving + 合成邮件链接 | 17.303 秒，2 次模型请求、1 次网页读取、0 次搜索、582 字回答、0 草稿、无协议泄漏；回答明确说明页面不完整 |
