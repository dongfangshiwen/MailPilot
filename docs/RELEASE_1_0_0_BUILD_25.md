# MailPilot 1.0.0（25）· 完整图文请求与侧栏交互修复

保持 1.0.0，内部构建号 24 → 25；原包名、发布签名及 Room v9 不变。请直接覆盖安装，不要先卸载。设置页读取 APK 实际版本。

## 原因与修复

旧流程在构建完整上下文之前，根据预估批数决定是否调用视觉助手。火山套餐接口没有已核实的上下文规格，保留的 32,768 配置加上每图 8,192 Token 的保守估算，可能让五图进入多次读图。服务端数量或请求体错误也曾触发自动拆分。这是客户端路由问题，不能证明厂商不支持图文同传。

- 当前视觉主模型直接接收本轮问题、选中邮件／文档文字及全部未缓存图片，普通回答流式显示 Markdown。没有辅助逐图 JSON 请求。
- 先构建完整请求，再按统一预算整理历史。未核实的图片 Token 估算单独记录为参考，不用它提前拒绝请求或产生负的压缩空间。
- 火山标准 `/api/v3` 与套餐 `/api/plan/v3` 分开识别。套餐额度暂未核实，不套用标准规格，不改地址、密钥或已有自定义额度。
- 请求体按最终 JSON 与 Base64 编码计算；保留流式文件编码及 32 MiB 应用上限。每轮仍最多 20 张视觉资料、10 个附件、合计 50 MB，单文件 20 MB。
- 只有文字主模型，或接口明确报告不支持图片，才进入助手读取流程。权限、限流、超时、格式问题不会自动换模型或分批。
- 真实超限时保留问题、资料及处理结果，点击“选择处理方式”可调整资料、选择“分批处理本轮”或返回。分批仅作用于本轮未完成图片；视觉主模型使用自身读取后汇总。后续新问题恢复完整图文优先。
- 同账号、同会话内复用已完成分析，支持追问、编辑重发、追加图片、重启和手动重新核对。部分助手观察保留；未完成主回答不当作成功缓存。
- 正常进度显示“正在分析 N 张图片”；只有明确选择分批后显示分批进度。诊断区分带图请求、累计上传图片、缓存命中、上下文整理和实际处理方式。

厂商限制沿用离线核实目录：[百炼视觉接口](https://help.aliyun.com/zh/model-studio/vision)、[DeepSeek 视觉接口](https://api-docs.deepseek.com/zh-cn/guides/vision/)、[火山视觉文档](https://docs.volcengine.com/docs/82379/1362931?lang=zh)。火山统一张数与套餐请求体上限仍标记未核实；32 MiB 是应用限制。实测成功张数不是官方最大张数。

## 侧栏与重命名

- 多选直接在当前侧栏显示，保留搜索框、筛选内容、同一个列表和滚动位置；不跳转页面、不强制回到顶部。
- 标题区显示已选数量，底部显示置顶和删除；退出多选回到原列表位置。
- 置顶与删除使用统一的简洁细线图标；长按菜单、多选操作栏与行内置顶标记复用同一绘制组件，文字和点击区域保持清晰。
- 会话行统一处理点击与长按，移除嵌套手势组件。重命名输入框取消浮动标签，标题、输入与操作分区；键盘打开后可滚动，支持长名称和大字体。
- 邮箱类型去掉勾选图标和预留图标空位，改为等宽、等高的选项按钮，用浅色背景、边框和字重表示当前选中。按屏幕及字体自适应列数，保留至少 48 dp 点击区域；切换不移动表单位置。
- 模型设置移除“支持视觉／目录核实日期”说明条及其多余的界面判定，后台能力目录、视觉路由和实际上下文配置继续生效。
- 截图使用本地示例：[多选](screenshots/build25/sidebar-multi-light.png)、[重命名](screenshots/build25/rename-light.png)、[软键盘打开](screenshots/build25/rename-keyboard-light.png)、[邮箱类型](screenshots/build25/mail-provider-light.png)、[模型设置](screenshots/build25/model-form-light.png)、[超限处理](screenshots/build25/image-choice-light.png)。

## 实际验证范围

火山真实验证运行在 API 36 临时模拟器内，通过 APK 中的 `LocalAgent → AndroidAttachmentProcessor → CompatibleModelClient`，使用 `doubao-seed-evolving` 和用户提供的套餐连接。上下文保持 32,768，思考关闭，输出 4096，只使用合成图片和示例邮件正文，没有调用 SMTP。

| 图片数 | 生成／带图请求 | 编码后请求体 | 首个正文增量 | 完成耗时 |
|---|---|---:|---:|---:|
| 5 | 1 / 1 | 72,508 字节 | 4,386 ms | 5,408 ms |
| 10 | 1 / 1 | 115,251 字节 | 3,737 ms | 5,113 ms |

同一请求包含完整问题和所选正文，返回包含全部印刷编号。数据库重开后用模拟回答端检查复用路径，两组追问上传数均为 0。这项缓存检查不是第二次真实模型回答的准确率验证。耗时为该设备与网络上的单次样例，不代表全部图片或物理手机性能。[原始记录](test-evidence/build25/ark-full-agent-live.json)

火山标准接口、百炼、DeepSeek 的路由通过本地回归验证，本轮没有使用它们的真实密钥测试。测试区分正常结束、断流、读取超时、401／403／429、服务端超限、精确请求体拦截、取消及旧快照兼容。完整统计与升级证据见 [验证记录](test-evidence/build25/validation-summary.json)。

Flutter 全量回归 318 项；最终侧栏交互 32 项、邮箱与模型设置 33 项通过。原生单元测试 167 项中 2 项按条件跳过，其余通过；Lint 无错误，保留 13 条工具链／既有警告。API 36 原生常规测试及独立火山真实测试通过。设备 UI 测试断言通过后，宿主截图导出连接中断；缺失图片已从签名 APK 的本地样例界面补拍，原始日志保留。重命名另检查了实际软键盘打开状态。

## 审查与交付

删除预估批数触发助手、大小错误自动切助手和未授权自动拆分分支。旧请求选项缺省为完整图文；显式分批保存在轮次 JSON。保留账号隔离、资料快照、缓存版本、取消及邮件发送确认检查。模型没有 SMTP 工具。

诊断只记录阶段、型号、主机、请求标识、计数、时间、额度、结束原因及异常类型，不记录正文、图片或凭据。真实测试凭据仅注入临时测试应用私有目录，测试后删除；源码包不含签名、密钥及本地缓存。

Windows：`scripts/Build.ps1 -Mode Verify` 执行静态检查、单元测试及构建；可加 `-DeviceTests -Device <设备编号> -ExpectedApi 36` 运行设备流程。`scripts/Package-Delivery.ps1` 打包源码、APK、中文说明和截图并计算 SHA-256。真实服务测试须单独提供凭据，默认设备回归跳过此项。

交付文件位于 `artifacts`，沿用 `MailPilot-1.0.0-flutter-release.apk` 文件名，并附同名 `.sha256`；完整交付包包含源码及脚本。覆盖升级验证保留配置、聊天、摘要、独立草稿、资料、置顶及视觉缓存。仅清理本轮临时设备和构建缓存，保留日常设备、镜像和用户资料。
