# MailPilot 1.0.0（35）：草稿删除样式与工具 JSON 解析修复

日期：2026-09-10。版本仍为 **1.0.0**，内部构建号 **35**；设置页不显示构建号。Room 保持 v9。

## 原因与修复

旧版 `AgentActions.normalize` 把整段模型正文传给 `JSONObject`。如果模型先写一句说明，再输出完整的 `mailpilot_action` 对象，整段文字无法当成 JSON 解析，随后却统一报“操作 JSON 不完整”。因此，这条错误不能单独证明网络截断或模型真的漏了括号。

本轮使用截图中的说明文字加完整读取对象，通过分片 HTTP 流和完整 Agent 路径复现并验证修复。没有取得截图中请求 `d4557e95-882b-42c6-b65d-fa2b18d75fa2` 的原始模型返回，所以不宣称该次原始 JSON 必然完整。

| 方面 | 修复前 | 修复后 |
|---|---|---|
| 说明文字＋完整 JSON | 可能误报 JSON 不完整 | 先定位独立的操作对象，再严格解析与校验 |
| 多个读取对象 | 首个对象后的内容可能被忽略 | 最多四个操作，全部通过校验后执行；最后一个残缺也不会先执行前面的对象 |
| 参数校验 | `JSONObject` 存在宽松解析行为 | 共用严格 JSON 读取，拒绝重复字段、尾随值、过深嵌套及不符合工具 schema 的参数 |
| 原生与文本格式重复出现 | 使用专门的兼容判断 | 两种表示必须完全一致，只执行一次；冲突时拒绝 |
| 真正残缺且已有搜索资料 | 整轮直接失败 | 不执行该操作，使用预留的无工具回答阶段，说明未核实部分并提供“继续检索” |
| 收尾失败重试 | 可能再次遇到旧的坏操作 | 保留成功资料和回执，丢弃无效待执行对象，只恢复最终回答 |
| 多操作反馈 | 文本模式仅记录首个动作 | 每个已执行动作都进入反馈，保持决策与结果对应 |
| 本地格式错误诊断 | 可能只有 `y50` 等混淆类名 | 新记录显示稳定的 `action_format` 类别、解析阶段及校验原因 |

## 通用架构与代码审查

- `ActionJson` 只处理协议边界及 JSON 语法；没有公司名称、搜索主题或截图句子的业务分支。
- `AgentActions` 继续统一检查工具白名单、必填字段、参数类型、范围和调用标识。带说明或多个对象的兼容路径只允许只读操作，不借格式兼容开放草稿修改或发送权限。
- `ResearchProgress` 负责阶段收尾和检查点恢复。格式错误使用已经预留的最终回答步骤，不增加模型修复循环，不自动重发失败网络请求。
- 流式展示继续复用现有协议隐藏逻辑，参数 JSON 不逐字显示到正文；没有新造一份显示过滤器。
- 清理旧的“整段正文解析＋包含字段名就报不完整”分支，合并参数解析，修复文本模式只反馈第一个操作的旧逻辑。
- 严格 JSON 拒绝重复键和尾随对象，避免同一输入在不同解析器间产生不同解释。引用块、行内代码和嵌套示例不作为可执行根对象。
- 真正不完整、超限或未授权的操作不会通过补括号、猜参数、删除字段的方式执行。没有有效搜索资料时仍保留失败与手动重试；最终回答本身失败时也不冒充成功。
- 账号／会话隔离、来源范围、草稿版本和发送确认机制保持；没有新增 SMTP 工具。当前问题不触发未选择邮箱或附件的读取。

## 删除草稿样式

对话页和草稿列表共用的草稿菜单，以及草稿编辑页的“删除草稿”，统一引用左侧栏的同一份矢量路径、**16px** 图标和 **`#EC1313`** 颜色。删除确认、禁用状态和发送状态保护的既有回归通过；没有复制一份 SVG，也没有更改整个应用的错误主题色。
