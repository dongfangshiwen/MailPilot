# MailPilot 1.0.0（34）发布与测试说明

日期：2026-09-10。版本继续为 **1.0.0**，内部构建号 **34**；设置页不显示构建号，保留发送确认提示。Room 保持 **v9**。

## 本轮改进

- 检索分为资料收集与最终回答。最多七轮工具决策后进入无工具的回答阶段；连续两轮没有新增资料时提前收尾。已有结果可形成带引用的部分回答，用户可点“继续检索”。普通检索不再因为用尽八轮而显示草稿相关报错。
- 重试恢复失败阶段。旧记录已用尽八轮时直接生成最终回答；“继续检索”开启新的有限收集阶段，保留已完成操作、来源和读取范围。
- 相同只读请求复用回执；不同查询返回相同来源、重复或重叠读取范围不作为新的有效进展。旧工具结果改为短回执与共享来源索引，最新必要结果保留，避免反复调用整理模型。
- 搜索摘录与网页正文明确区分。网页只能按当前资料的来源编号读取，每阶段最多八页、最多两路并发；每页成功后立即保存检查点。
- 思考、搜索、实际网页阅读与复用显示在一个稳定的可折叠过程区，使用真实数量和站点。保留手动展开与阅读位置；末尾导航只有箭头，不显示说明文字。工具协议不进入正文和过程区。

完整前后对比见 [优化前后文档](OPTIMIZATION_BEFORE_AFTER_1_0_0_BUILD_34.md)。

## 代码审查与冗余清理

| 审查发现 | 本轮处理 |
|---|---|
| 八轮直接抛错、耗尽检查点恢复后再失败 | 删除旧的循环上限失败分支，统一用 `ResearchProgress` 收尾与恢复 |
| 旧的重复调用集合与新进展判断并存 | 移除无用的 `seen` 访问逻辑，保留旧 JSON 的必要兼容读取 |
| 重复工具摘要、同一来源多份摘录 | `ToolContextView` 合并为回执及单份索引；视图按实际剩余预算生成 |
| 网页正文在进度状态和来源中重复保存 | 进度只存状态，正文进入按账号、会话隔离的 `WebEvidenceStore` |
| 多份大网页进入同一 Room JSON 行，存在行大小风险 | 完整正文存本地文件，JSON 只存内容指纹及最多 4,000 字符预览；这是预览上限，不是正文截断或摘要长度校验 |
| 缓存文件失效、串用或被改动 | 按账号和会话目录定位，校验 SHA-256，不接受任意文件路径；失效时标为摘录并允许重读 |
| 并发网页读取中成功结果可能等失败项后才保存 | 成功项立即落文件和检查点，取消后保留，恢复只补未完成项 |
| 重复来源视图解析与文字边界处理 | 查询词只解析一次，摘录边界避免拆开 UTF-16 代理对；去掉未使用的网页结果字段及重复正文赋值 |
| 搜索部分失败时重复上报完成事件 | 合并为单次终态通知；完全失败时仍先记录失败状态再退出 |

没有针对某个公司、产品或用户问题写死检索关键词。源代码改动目录见 [文件清单](test-evidence/build34/changed-files.json)。

网页客户端独立于邮箱和模型，不携带其凭据。每次连接使用经公网校验的 DNS 结果，并校验重定向地址；禁止内网、回环、链路本地及其他非公网目标。连接 10 秒、单页总时限 30 秒、重定向最多三次，解压后响应最多 2 MiB；仅提取 HTML／纯文本，不执行脚本。登录、动态内容、非文本文件和连接失败均保留摘录并返回明确状态。

缓存随删除所属会话、账号或用户主动清理聊天缓存回收。图片分析缓存、草稿版本和发送确认机制保持；模型工具中没有 SMTP，测试没有发送邮件。

## 真实接口对照

测试设备为已有 **MailPilot_API36 / API 36**。使用设备已配置的 **doubao-seed-evolving** 和真实联网搜索，通过完整 `LocalAgent` 路径处理临时资料库中的合成邮件、五张编号图片及四组历史问答。思考启用、快速整理启用，保留原模型上下文与输出设置。没有使用真实邮件正文作为测试输入。

| 场景 | 构建 33 总耗时 | 构建 34 总耗时 | 模型请求 33→34 | 搜索查询 33→34 |
|---|---:|---:|---:|---:|
| 首次分析与检索 | 74.745 秒 | 41.556 秒 | 8→4 | 4→2 |
| 复用图片后的追问 | 34.044 秒 | 39.918 秒 | 1→1 | 0→0 |
| 请求前模拟失败后的重试 | 24.323 秒 | 12.336 秒 | 1→1 | 0→0 |

最终首次样例没有额外的工具结果整理请求；保留一次资料整理。图片助手与正式回答的实际请求仍分别计数。此次原配置走文字工具适配路径，不能把本表理解成所有视觉主模型都需要助手。

首次开发版本实际耗时 **136.232 秒、10 次模型请求、6 条搜索查询、2 页网页读取**，比旧版更慢。根据这次结果继续修改共享来源索引和工具视图预算，才得到上表结果。最终简单任务用搜索摘录即可回答，因此没有额外打开网页；这与按需读取的目标一致。

追问并未更快；服务排队、生成长度、网络和模型决策会波动。以上各场景为单次真实样例，不能当成统计性能保证，也不能与 DeepSeek APK 的内部服务或速度等同。构建 33 的基线样例成功，用户截图那次八轮调用的完整原始序列没有取得；循环问题由完整 Agent 的受控回归覆盖。

原始元数据：[旧版](test-evidence/build34/live-baseline33.json)、[首次开发实测](test-evidence/build34/live-current34.json)、[最终实测](test-evidence/build34/live-final34.json)。不含正文、图片和凭据。

另在 API36 使用独立公网客户端读取 IANA 官方页面，真实网络请求 **1 次**，读取并写入缓存后重新加载，第二次 **0 次联网**；全流程 **1.523 秒**。见 [网页缓存测试](test-evidence/build34/live-page-cache.json)。这项单独验证真实网页与文件缓存，不冒充真实模型测速。

本轮没有可用的 DeepSeek 配置用于相同设备实测，未补造 DeepSeek 真实接口结果；厂商中断或不遵守工具协议仍可能失败，应用会保留已完成资料供重试。
